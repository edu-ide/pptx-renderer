# v1.3.0 Release Notes

Release date: 2026-09-14

## Summary

v1.3.0 is a backward-compatible minor release that expands browser rendering for common
PowerPoint content and adds bounded support for equations, static DrawingML 3D, shadows, and
reflections. It also improves CJK text, tables, 2D charts, generated geometry, media fallbacks, and
reproducible visual validation against native PowerPoint output.

## Added

- A pinned ECMA-376 geometry runtime for all 28 zero-adjustment flowcharts and bounded `donut`
  adjustments.
- Browser-native rendering for a bounded OMML subset covering common fractions, radicals,
  scripts, delimiters, n-ary operators, matrices, and functions, with package-authored fallback
  content for unsupported formula trees.
- Bounded static DrawingML 3D for selected bevel, camera-plane, picture, text, custom-geometry, and
  group combinations, plus validated ordinary-shape outer shadows and reflections.
- Embedded EOT/MTX font loading and reproducible browser, font, PPTX, ground-truth, and renderer
  provenance for visual evaluation.

## Improved

- CJK wrapping, Office percentage spacing, paragraph edges, text color precedence, styled soft
  breaks, and selected `spAutoFit` growth.
- Common table styles, merges, cell margins and anchors, conditional borders, and direct cell
  overrides.
- 2D chart defaults and layout, combo/secondary-axis cases, sparse and literal data sources,
  explicit zeros, and negative-value behavior.
- Compatible-content selection, placeholder and color-map inheritance, SVG/OLE previews, clipped
  picture effects, group transforms, and asynchronous media cleanup.

## Support Boundaries

The new 3D and effect paths cover the native-validated combinations documented in the repository.
General extrusion, arbitrary camera or lighting scenes, true 3D charts, embedded Office 3D models,
animation playback, transitions, complete OMML, arbitrary EMF/WMF vector rendering, and executable
OLE objects remain outside this release.

## Migration Notes

No API migration is required. `pdfjs-dist` remains optional and is needed only for supported
embedded-PDF preview fallbacks. Visual fidelity still depends on available fonts and package
fallback content.
